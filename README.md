# 划词翻译 (hover-translate)

Chrome MV3 扩展：网页里划选英文 → 弹出中文译文，走大模型接口；相同内容命中本地记录，不再重复请求。

## 安装

1. Chrome 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录 `hover-translate`

加载后到弹窗 →「设置」里填接口地址（任何 OpenAI 兼容的 `/chat/completions` 服务）、API Key 和模型名，点「测试连接」确认可用。

不想每次重装都填一遍，可以把 `config.local.example.json` 复制成 `config.local.json` 并写上自己的接口地址和 Key。这个文件已在 `.gitignore` 里，只作为本机默认值；设置页保存的配置优先于它。

## 用法

- **划选即译**：鼠标划选英文，译文卡片出现在选区附近。单词给词性+义项，短语给含义，句子给整句翻译；单词和短语下方额外给一句英文例句及其中文翻译。
- **右键翻译**：已选中的文本 → 右键 →「划词翻译：译为中文」（适合不想自动弹卡片的场景）。
- **关闭自动翻译**：扩展弹窗里取消「选中即翻译」，之后划选只显示浮动「译」按钮，点一下才翻译。
- **缓存命中**：相同内容第二次是毫秒级返回，不消耗模型额度。旧版本（无例句）的记录在下次划到时会重新请求一次。
- **朗读**：卡片上的 🔊 用系统 / Chrome 自带语音（Web Speech API）朗读原文，点一下朗读、再点停止；设置页可开「翻译出结果后自动朗读」、调语速、选音色（Chrome 里能看到本机全部音色）。
- **复制 / 收藏**：卡片上有复制译文、收藏（收藏项在记录页置顶）。
- **token 花费**：卡片上不再显示；每条记录的 token 用量在记录页可见，填好输入/输出单价（元/百万 tokens）后弹窗与记录页汇总累计输入/输出 tokens、模型请求次数、缓存命中次数与预估总费用。
- **翻译记录**：弹窗 →「翻译记录」，可搜索原文/译文、只看收藏、复制、删除、清空；每行带该条的 token 用量。
- **精读**（v0.2）：选中一句或一段（≥3 个词）→ 卡片上的书本图标 / 右键「划词翻译：精读这段」/ 快捷键 `Alt+R`（在 `chrome://extensions/shortcuts` 可改；侧栏开着且没有选区时再按一次关闭）。右侧滑出侧栏：
  - **逐句**：主谓宾、从句、非谓语、插入语着色（悬停看说明），中文译文，「怎么读」，搭配，重点词（语境义 + 常见义），语法难点，难度；🔊 朗读整句
  - **点词**：点句中任意单词，按这句的语境给释义，可直接加入生词本
  - **词汇**：全段重点词汇总；**主旨**：多句时给一句话主旨 + 句间逻辑
  - 本地分句后每句并发请求（并发 3），先回来先显示；按句缓存，同一句再精读不花 token；单次上限 12 句 / 3000 字符
  - 重点词按设置页「英语水平」筛（四级 / 六级 / 考研 / 雅思托福 / 不限，默认六级）
- **全文精读**（v0.3）：读长文章时不用选中。弹窗点「精读本页全文」/ 在页面空白处右键「划词翻译：精读全文」/ 没有选区时按 `Alt+R`，扩展自动识别本页正文并打开侧栏：
  - **自动识别正文**：找出承载大部分段落文字的容器，跳过导航、侧栏、评论、页脚和非英文内容，保留小标题
  - **随读随析**：只分析侧栏里看得到的段落，并往后预取一段，读到哪分析到哪，不会一次把整篇文章都送去模型；已精读过的句子走缓存
  - **跟随原文**：滚动网页时侧栏自动跟到正在读的那一段，网页里这一段会淡紫色标出；点侧栏段首的「定位原文」反向跳回网页。不想跟随时点掉「跟随原文」
  - **导读**：打开时用一次请求给出全文主旨、文章结构（点某一部分跳到对应段落）和阅读提示
  - 逐句拆解、点词、加生词、词汇汇总与选中精读一致；单篇上限 800 句
- **在新标签页打开**：精读侧栏右上角的「↗」按钮，把当前精读的内容（选中的一段或整篇文章）搬到独立标签页，整页宽度阅读，不再挡住原网页。已分析过的句子直接走缓存；页面右上角「原网页」可回到出处。独立页面里没有「跟随原文」和「定位原文」。内容存在精读记录里，标签页刷新或重开浏览器后仍能打开。
- **精读记录**：全文精读会自动记一条（同一网址只留一条），记录页 →「精读记录」里能看到篇幅、读到百分之几、最近阅读时间，点标题在独立标签页重新打开并回到上次读到的段落。记录保存的是原文和分句，逐句分析结果来自精读缓存，读过的句子不再花 token。选中精读只有点了「在新标签页打开」才会记一条。最多保留 30 条，超出按最久未读淘汰。
- **生词本**（v0.2）：精读侧栏或点词浮层点「＋生词」；单词 / 短语（≤4 个词）的划词卡片上点书签图标。会存语境释义、所在原句、来源网页。
  - 记录页 →「生词本」：搜索、按待复习 / 学习中 / 已掌握筛选、删除，导出 CSV 或 Anki（Anki 里「导入」，分隔符选制表符，勾选允许 HTML）
  - 「复习」：看单词和原句回想意思 → 空格看释义 → `1` 不认识 / `2` 模糊 / `3` 认识。不认识 10 分钟后到期且本轮末尾再出现一次；认识按 1 → 3 → 8 → 20 天拉长，模糊 ×1.2；间隔 ≥21 天算已掌握
  - 网页里出现生词本中的词会淡黄底 + 虚线标出（CSS Highlight API，不改页面 DOM，设置页可关）
- **设置**：弹窗 →「设置」，可改接口地址、API Key、模型名、温度、超时，以及朗读（自动朗读 / 语速 / 音色，带试听）和费用（输入、输出单价）；「测试连接」会真实发一次翻译请求验证配置，并回报本次 tokens 与费用；「先思考再作答」默认关闭（开启会带回推理 token，费用上升）。

## 默认模型

| 项 | 值 |
| --- | --- |
| 接口 | `https://api.deepseek.com/v1`（可换成任何 OpenAI 兼容 `POST /chat/completions` 的地址） |
| API Key | 空，需要自己填 |
| 模型 | `deepseek-v4.1-flash` |
| 备选 | 设置页模型下拉里有 `deepseek-v4-pro-0813`、`qwen3.8-max`，也可手填 |

## token 与费用

- **默认不发思考请求**：请求体带 `reasoning_effort: "none"`（可在设置页「先思考再作答」里打开）。同一个网关实测同一句话输出从 92 tokens 降到 5 tokens；本扩展端到端实测从「入 164 / 出 194」降到「入 139 / 出 10」，三条文本累计从 1239 tokens 降到 425 tokens。翻译任务不需要推理链，这些 token 纯属浪费。
- 每次请求把网关返回的 `usage` 存进记录：`prompt_tokens` / `completion_tokens` / `total_tokens`，并保留 `cached_tokens`、`reasoning_tokens` 明细（鼠标悬停记录页 tokens 列可见）。
- 累计口径：只有真正打到模型的请求才计入 `tokensIn / tokensOut / tokensTotal / tokenRequests`；缓存命中只增加 `hits`，不会重复计 token。
- 费用是本地估算：`输入 tokens × 输入单价 + 输出 tokens × 输出单价`（单价按百万 tokens 计）。单价留 0 则只显示 token 用量，界面提示「未配置单价」。真实计费以网关账单为准。

## 缓存与记录

- 存储在 `chrome.storage.local`，键是文本归一化后的形式（大小写不敏感、空白折叠），所以 `The  Quick Brown Fox` 与 `the quick brown fox` 命中同一条记录。
- 记录保留 180 天，最多 3000 条，超出按最久未使用淘汰。
- 记录条数、缓存命中数、模型请求数、累计 tokens 与预估费用在弹窗和记录页可见。

## 隐私

- 只有主动触发时才把文本发给你配置的模型接口：划选/右键发选中的文本；全文精读发本页正文（导读一次请求带上各段开头，之后按阅读进度逐句发送）。不触发就不读取、不上传页面内容。
- API Key 存在 `chrome.storage.local`（或本机的 `config.local.json`），只会发给你填的接口地址。`manifest.json` 声明了 `https://*/*` 的访问权限，是为了让接口地址可以自由配置。
- 翻译记录仅在本机浏览器内，清空按钮可一键删除。

```bash
node test/deep-e2e.mjs             # 32 项真实 Chrome + 真实模型：整段精读→着色/主旨/tokens→点词释义→加生词→网页标词→二次精读全命中缓存→单词卡片加生词→生词本页→复习评分
```

`test/e2e.mjs`、`test/ui.mjs` 需要 `puppeteer-core`（脚本内按绝对路径加载 Chrome for Testing）：

```bash
mkdir -p node_modules && ln -s <某处>/node_modules/puppeteer-core node_modules/puppeteer-core
```

端到端脚本会真的调用模型接口（消耗额度），需要先在 `config.local.json` 里配好可用的接口和 Key；Chrome for Testing 的路径用 `CHROME_EXE` 指定。全文精读目前只有单元测试，还没有端到端脚本。

## 已知限制

- 输入框（`<input>`/`<textarea>`/`contenteditable`）里的选区不弹卡片，避免干扰表单输入。
- 单次翻译上限 4000 字符；选中精读单次上限 12 句 / 3000 字符；全文精读单篇上限 800 句。
- 正文识别是启发式的：排版特殊的页面可能漏段或带进少量无关内容；只处理顶层页面，不进 iframe；页面内容在打开侧栏后又动态变化的，需要重新触发一次。
- 精读的成分着色靠模型给出的原文片段定位，个别片段对不上原文时只是不着色，不影响译文和讲解。
- 网页标词只认生词本里的原形及 s/es/ed/d/ing 等常见变化，不做完整词形还原（如 went ↔ go）。
- 缓存是归一化后的精确匹配，不做模糊/近义匹配。
- 未覆盖 `chrome://`、扩展商店等受限页面（浏览器不允许注入）。
- 本地文件（`file://`）需要在扩展详情页打开「允许访问文件网址」才生效。
- 朗读依赖系统/Chrome 自带语音；某台机器没有英文音色时会退回系统默认音色（音色列表由浏览器提供）。
- token 与费用只按接口返回的 `usage` 统计，若网关不返回 `usage`（部分代理会省略），则显示「接口未返回 token 用量」。
- 单价是本地估算，网关若按缓存命中价、推理价等分级计费，这里不会自动区分。
- `reasoning_effort` 属于兼容参数：换成不支持该字段的网关时通常会被忽略；若网关明确报未知参数，请在设置页把「先思考再作答」打开（此时不带该字段）。
